# 知识记忆系统 - 面试准备

## 一、系统概述

基于 ChromaDB + BGE 向量模型构建的长期记忆系统，支持对话、任务、知识三类数据的语义检索，实现跨会话知识积累。

---

## 二、架构设计

### 2.1 三类记忆存储

```
┌─────────────────────────────────────────────────────────┐
│                    LongTermMemory                        │
├─────────────────┬─────────────────┬─────────────────────┤
│ conversations   │     tasks       │     knowledge       │
│   对话记忆      │    任务记忆     │      知识记忆       │
├─────────────────┼─────────────────┼─────────────────────┤
│ 用户消息        │ 任务描述        │ 论文标题            │
│ 助手回复        │ 执行结果        │ 论文摘要            │
│ 时间戳          │ 任务类型        │ 作者/关键词         │
│ 会话ID          │ 评估分数        │ 数据来源            │
└─────────────────┴─────────────────┴─────────────────────┘
                          │
                          ▼
              ┌───────────────────────┐
              │   ChromaDB 向量存储    │
              │   BGE-small-zh-v1.5   │
              └───────────────────────┘
```

### 2.2 核心流程

```
用户请求 → 关键词检测 → 向量检索 → 上下文构建 → 注入 Prompt
    │           │            │            │
    │           │            │            └─ 格式化为可读文本
    │           │            └─ 余弦相似度匹配
    │           └─ "上次"、"之前"、"记得"等触发词
    └─ 存储执行结果到对应 Collection
```

### 3.2 存储记忆

```python
def save_task(self, user_id, task_id, task, result, task_type, evaluation_score):
    # 构建文档内容
    doc = f"任务: {task}\n结果: {json.dumps(result, ensure_ascii=False)[:2000]}"
    
    # 存入向量数据库
    self.task_collection.upsert(
        documents=[doc],                    # 文本内容（自动向量化）
        metadatas=[{                        # 元数据（过滤条件）
            "user_id": user_id,
            "task_type": task_type,
            "evaluation_score": evaluation_score
        }],
        ids=[f"task_{task_id}"]             # 唯一标识
    )

def save_knowledge(self, paper_id, title, abstract, authors, keywords, source):
    doc = f"标题: {title}\n摘要: {abstract}\n关键词: {', '.join(keywords)}"
    self.knowledge_collection.upsert(documents=[doc], metadatas=[...], ids=[...])
```

### 3.3 语义检索

```python
def recall_similar_tasks(self, task, user_id, n_results=3):
    # 向量相似度查询 + 元数据过滤
    results = self.task_collection.query(
        query_texts=[task],              # 查询文本（自动向量化）
        n_results=n_results,             # 返回数量
        where={"user_id": user_id}       # 元数据过滤
    )
    return self._format_query_results(results)

def search_knowledge(self, query, user_id, n_results=10):
    # 跨条件组合过滤
    where_filter = {"$and": [
        {"source": source},
        {"user_id": user_id}
    ]}
    results = self.knowledge_collection.query(
        query_texts=[query],
        n_results=n_results,
        where=where_filter
    )
    return results
```

### 3.4 记忆上下文构建

```python
class MemoryContextManager:
    MEMORY_KEYWORDS = ["昨天", "上次", "之前", "记得", "历史", "那些论文"]
    
    def should_use_memory(self, current_task):
        return any(kw in current_task for kw in self.MEMORY_KEYWORDS)
    
    def get_memory_for_query(self, query, user_id):
        # 并行检索三类记忆
        similar_tasks = self.memory.recall_similar_tasks(query, user_id)
        relevant_papers = self.memory.search_knowledge(query, user_id)
        conversations = self.memory.recall_conversations(query, user_id)
        
        return {
            "similar_tasks": similar_tasks,
            "relevant_papers": relevant_papers,
            "conversations": conversations,
            "has_relevant_memory": bool(similar_tasks or relevant_papers)
        }
    
    def format_memory_for_prompt(self, memory_data):
        # 格式化为 LLM 可理解的上下文
        parts = ["以下是相关的历史记忆，请参考："]
        if memory_data.get("similar_tasks"):
            parts.append("\n【相似任务】")
            for t in memory_data["similar_tasks"]:
                parts.append(f"- {t['metadata'].get('task', '')}")
        return "\n".join(parts)
```

## 四、面试问答准备

### Q1: 为什么选择 ChromaDB 而不是其他向量数据库？

**回答要点：**
- **轻量级**：嵌入式部署，无需独立服务，适合桌面应用
- **持久化**：支持本地磁盘存储，数据不丢失
- **易用性**：Python API 简洁，自动处理向量化
- **功能够用**：支持元数据过滤、相似度查询，满足需求
- **对比 Pinecone/Milvus**：它们需要云服务或独立部署，对小项目过重

**追问方向：** 数据量大了怎么办？
- 回答：可以迁移到 Milvus/Qdrant，ChromaDB 支持数据导出

---

### Q2: 为什么选择 BGE-small-zh-v1.5 作为向量模型？

**回答要点：**
- **中文优化**：BGE 对中文语义理解更好
- **轻量级**：small 版本约 33M 参数，推理速度快
- **效果足够**：在 MTEB 中文榜单表现优秀
- **对比 OpenAI Embedding**：本地运行，无 API 成本，隐私友好

**追问方向：** 效果不好怎么办？
- 回答：可以升级到 bge-base 或 bge-large，或尝试多语言模型

---

### Q3: 三类记忆为什么要分开存储？

**回答要点：**
- **语义差异**：对话是问答对，任务是执行记录，知识是论文元数据
- **检索效率**：分开存储可以针对性查询，避免噪声
- **元数据不同**：对话需要 conversation_id，任务需要 evaluation_score
- **扩展性**：可以独立优化每个 Collection 的索引策略

---

### Q4: 如何判断是否需要检索记忆？

**当前实现（基础版）：**
```python
MEMORY_KEYWORDS = ["昨天", "上次", "之前", "记得", "历史"]
def should_use_memory(self, task):
    return any(kw in task for kw in self.MEMORY_KEYWORDS)
```
- 基于关键词触发，简单高效
- 缺点：无法理解复杂语义，漏检率高

**前沿 Agent 的做法：**

| 方案 | 代表项目 | 核心思路 |
|-----|---------|---------|
| LLM 判断 | MemGPT/Letta | 专门的"记忆管理器"角色，LLM 自主决定检索 |
| 向量相似度 | RAG 系统 | 对所有查询检索，用阈值过滤低相关结果 |
| 实体提取 | LangChain Memory | 提取人名、时间、主题等实体，定向检索 |
| 分层记忆 | AutoGPT | 短期/长期/工作记忆分层，按需提升 |
| 上下文窗口 | Claude | 持续维护上下文，自动压缩旧记忆 |

**改进方案（可升级）：**

```python
# 方案1: 向量相似度预检索（推荐）
def should_use_memory_v2(self, task, user_id):
    # 先做一次快速检索
    results = self.memory.task_collection.query(
        query_texts=[task],
        n_results=1
    )
    # 如果有高相似度结果，则启用记忆
    if results['distances'][0][0] < 0.3:  # 距离阈值
        return True
    return False

# 方案2: LLM 分类器
MEMORY_CHECK_PROMPT = """判断以下任务是否需要检索历史记忆？
任务：{task}
需要检索的情况：引用之前结果、延续上次任务、查找历史论文
不需要的情况：全新问题、通用知识问答
只回答 YES 或 NO。"""

def should_use_memory_v3(self, task):
    result = self.llm.call(MEMORY_CHECK_PROMPT.format(task=task))
    return "YES" in result.upper()

# 方案3: 混合策略（关键词 + 相似度）
def should_use_memory_v4(self, task, user_id):
    # 关键词快速判断
    if any(kw in task for kw in self.MEMORY_KEYWORDS):
        return True
    # 相似度兜底
    return self._check_similarity(task, user_id, threshold=0.25)
```

**面试回答要点：**
- 当前用关键词匹配，简单高效但不够智能
- 前沿方案：MemGPT 用 LLM 自主决策，RAG 用相似度阈值
- 改进方向：混合策略（关键词 + 向量相似度），兼顾效率和准确性

### Q5: 向量检索的相似度阈值如何确定？

**回答要点：**
- ChromaDB 默认返回 distance（距离），越小越相似
- 实践中不设固定阈值，而是取 Top-K 结果
- 通过元数据（如 evaluation_score）二次过滤高质量结果
- 后续可通过 A/B 测试优化阈值

---

### Q6: 如何处理用户隐私和数据安全？

**回答要点：**
- **本地存储**：ChromaDB 数据存储在用户本地设备
- **用户隔离**：通过 user_id 元数据过滤，确保数据隔离
- **无云端依赖**：向量模型本地运行，数据不上传
- **可扩展**：支持加密存储，符合 GDPR 要求

### Q7: 记忆系统如何与 Agent 主流程结合？

**回答要点：**
```python
async def execute_task(self, task, callback, context_input, user_id):
    # 1. 判断是否需要检索记忆
    if self.memory_manager.should_use_memory(task):
        # 2. 检索相关记忆
        memory_data = self.memory_manager.get_memory_for_query(task, user_id)
        # 3. 构建上下文
        memory_context = self.memory_manager.format_memory_for_prompt(memory_data)
        enhanced_context["memory_context"] = memory_context
    
    # 4. 执行任务（带记忆上下文）
    result = await self.base_agent.execute_task(task, callback, enhanced_context)
    
    # 5. 存储执行结果
    self.memory.save_task(user_id, task_id, task, result, task_type)
```

### Q8: 跨平台路径适配如何实现？

**回答要点：**
```python
def get_chroma_path():
    if sys.platform == "win32":
        app_data = os.environ.get("APPDATA", "")
        return os.path.join(app_data, "AcademicAssistant", "chroma_longterm")
    else:
        home = os.path.expanduser("~")
        return os.path.join(home, ".academicassistant", "chroma_longterm")
```
- Windows: `%APPDATA%/AcademicAssistant/chroma_longterm`
- macOS/Linux: `~/.academicassistant/chroma_longterm`

- 记录日志，提示用户检查依赖

## 五、技术亮点总结

1. **三类记忆分离**：对话/任务/知识独立存储，检索更精准
2. **语义检索**：基于向量相似度，而非关键词匹配
3. **用户隔离**：元数据过滤确保多用户数据安全
4. **跨平台适配**：Windows/macOS/Linux 路径自动适配
5. **优雅降级**：存储不可用时系统仍可正常运行
6. **上下文注入**：记忆自动格式化为 LLM 可理解的 Prompt
