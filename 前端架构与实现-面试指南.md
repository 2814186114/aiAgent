## 二、双模式实时通信架构

### 技术背景
项目需要支持两种通信模式：
- **普通聊天模式**：使用 Socket.IO，支持轮询降级
- **任务规划模式**：使用原生 WebSocket，支持流式输出

### 核心实现

#### 1. Socket.IO 连接管理
```typescript
const connectSocket = useCallback(() => {
    if (socketRef.current?.connected) return

    socketRef.current = io(SOCKET_URL, {
        transports: ['websocket', 'polling'],
        reconnection: true,
        reconnectionAttempts: 10,
        reconnectionDelay: 1000,
    })

    const socket = socketRef.current

    socket.on('connect', () => {
        setIsConnected(true)
    })

    socket.on('agent-step', (step: AgentStep) => {
        setCurrentSteps(prev => [...prev, step])
    })

    socket.on('agent-complete', (data) => {
        setCurrentAnswer(data.answer)
        setIsProcessing(false)
    })
}, [])
```

#### 2. WebSocket 任务规划模式
```typescript
const ws = new WebSocket('ws://localhost:8000/ws/planning')

ws.onopen = () => {
    ws.send(JSON.stringify({
        type: 'start_planning',
        task: task.trim(),
        context: {
            messages: conversation.messages.slice(-10),
            currentPapers: conversation.currentPapers
        }
    }))
}

ws.onmessage = (event) => {
    const data = JSON.parse(event.data)
    if (data.type === 'progress') {
        setProgress(data)
    } else if (data.type === 'task_list') {
        setTasks(data.tasks)
    } else if (data.type === 'complete') {
        setResult(data.result)
        setLoading(false)
    }
}
```

### 面试问答

**Q: 为什么使用两种不同的通信方式？**

A: 两种模式有不同的需求：
- Socket.IO 适合普通聊天，支持自动重连、房间管理、轮询降级
- WebSocket 适合任务规划，需要更细粒度的流式控制和更低延迟

**Q: 如何处理连接断开？**

A: 实现了多层保障：
1. Socket.IO 内置重连机制（10次重试，1秒间隔）
2. 手动重连超时处理
3. 连接状态实时显示给用户

ws.onmessage = (event) => {
    const data = JSON.parse(event.data)
    
    if (data.type === 'task_update') {
        setTasks(prev => prev.map(t =>
            t.task_id === data.task_id
                ? { ...t, status: data.status }

                : t
        ))
    }
}

### 面试问答

**Q: 为什么不使用 Redux 或 Zustand？**

A: 项目规模适中，React Hooks + Context 足够应对：
1. 状态主要在组件内部流转
2. 跨组件状态通过 Context 传递
3. 避免引入额外复杂度

**Q: 如何避免状态更新导致的性能问题？**

A: 采用以下策略：
1. 使用 `useCallback` 缓存函数
2. 使用 `useRef` 存储不需要触发渲染的值
3. 状态更新时使用函数式更新 `setTasks(prev => ...)`

## 四、前端意图检测

### 实现原理

```typescript
const detectInputMode = (text: string): { mode: InputMode; hint: string; processedText: string } => {
    const lowerText = text.toLowerCase().trim()

    // 1. 显式命令检测
    if (lowerText.startsWith('/实验') || lowerText.startsWith('/experiment')) {
        return {
            mode: 'record',
            hint: '将记录为实验结果',
            processedText: text.replace(/^\/实验\s*/i, '')
        }
    }

    // 2. 关键词匹配
    const experimentKeywords = ['跑了', '测试了', '实验结果', '准确率', 'loss', '训练了']
    const reminderKeywords = ['提醒我', '别忘了', '明天', '下周', '组会']
    const queryKeywords = ['查看', '查询', '最近', '历史']

    for (const keyword of experimentKeywords) {
        if (lowerText.includes(keyword)) {
            return { mode: 'record', hint: `检测到实验关键词"${keyword}"`, processedText: text }
        }
    }

    return { mode: 'chat', hint: '将作为对话处理', processedText: text }
}
```

### 面试问答

**Q: 为什么在前端做意图检测？**

A: 前端意图检测有以下优势：
1. **即时反馈**：用户输入时就能看到识别结果
2. **减少请求**：不需要每次输入都请求后端
3. **用户体验**：提供可视化的模式提示

**Q: 关键词匹配的局限性？**

A: 确实存在局限性，但适合当前场景：
1. 学术场景关键词相对固定
2. 后端有 LLM 做二次确认
3. 可以逐步扩展关键词库

2. **防抖处理**：避免频繁渲染

- `pending`：等待执行
- `running`：正在执行（带动画）
- `success`：执行成功
- `error`：执行失败

A: 平衡上下文完整性和 token 限制：
1. LLM 有 token 限制
2. 太多历史消息会增加延迟

## 八、自定义 Hook 设计

### useConversation Hook

```typescript
export function useConversation() {
    const [currentConversationId, setCurrentConversationId] = useState<string | null>(null)
    const [conversations, setConversations] = useState<Conversation[]>([])
    const [loading, setLoading] = useState(false)

    const loadConversations = useCallback(async () => {
        const response = await fetch('http://localhost:8000/conversations?limit=50')
        const data = await response.json()
        if (data.success) {
            setConversations(data.conversations)
        }
    }, [])

    const createConversation = useCallback(async (title?: string) => {
        const response = await fetch('http://localhost:8000/conversations', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ title })
        })
        const data = await response.json()
        if (data.success) {
            setCurrentConversationId(data.conversation.id)
            return data.conversation.id
        }
    }, [])

    return {
        currentConversationId,
        conversations,
        loading,
        loadConversations,
        createConversation,
    }
}
```

### 面试问答

**Q: 自定义 Hook 的优势？**

2. **关注点分离**：UI 与业务逻辑解耦
3. **测试友好**：可以单独测试 Hook
